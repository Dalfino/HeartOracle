# ORACLE

**Local-first, CPU-only cardiac imaging analysis pipeline with fully-cited clinical report synthesis.**

> ⚠️ **RESEARCH PROTOTYPE — NOT FOR CLINICAL USE.**
> ORACLE is an advisory Clinical Decision Support (CDS) research system. It is not FDA-cleared,
> not a medical device, and must never be used for diagnosis or treatment decisions.
> All outputs require review by a qualified physician.

---

## Overview

ORACLE ingests a cardiac DICOM study (MR/CT), runs deterministic segmentation and volumetric
analysis on CPU, retrieves applicable clinical guidelines via RAG, and synthesizes a
**fully-cited surgical planning report** using a local quantized LLM. Every recommendation
carries a traceable guideline citation; every number is cross-checked by an automated auditor.

Design principles:
- **Deterministic core.** Geometry and physics are computed by validated models and explicit
  formulas — never generated by the LLM.
- **Grounded synthesis.** The LLM only translates retrieved facts; it cannot invent clinical content.
- **CPU-only, zero-cloud.** Runs end-to-end on a 4-core machine with no GPU and no network calls.
- **Privacy-first.** De-identification at ingestion; no PHI leaves the machine; optional analytics
  records are stored in an encrypted local vault.

## Architecture

```
DICOM study (dir/zip)
   │  oracle ingest          → de-identify (DICOM PS3.15-style tag blanking) → study.json
   ▼
2.5D U-Net (ONNX INT8, CPU)
   │  oracle segment         → per-slice masks → volumes, confidence → seg.json
   ▼
Volumetrics (Simpson slice-summation)
   │  oracle physics         → EDV / ESV / EF → phy.json
   ▼
Guideline RAG (ChromaDB + bge-small-en-v1.5)
   │  (internal)             → top-3 cited chunks (min cosine 0.25)
   ▼
Local LLM (Phi-3.5-mini Q4_K_M, llama.cpp, temp=0)
   │  oracle report          → ORACLE-SYNTH prompt → draft report
   ▼
Auditor (numeric cross-check + citation coverage + disclaimer)
   │                         → report.md  (or AUDIT FAILED banner, exit 5)
   ▼
[optional] oracle vault     → encrypted local analytics record (ORACLE_ANALYTICS=1)
```

## Installation

```bash
git clone <repo-url> oracle && cd oracle
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

### Fetch assets (one-time)

1. **Segmentation model (ONNX INT8).** Run `notebooks/kaggle_export_onnx.ipynb` on Kaggle
   (free GPU), which evaluates on the ACDC test split, exports ONNX (opset 17), applies
   `quantize_dynamic(QInt8)`, and publishes dataset `oracle-seg-v1`. Then:
   ```bash
   kaggle datasets download -d <your-user>/oracle-seg-v1 -p models/ --unzip
   ```
   Expected contents: `seg.onnx`, `seg_int8.onnx`, `meta.json`, `metrics.csv`.
2. **Local LLM (GGUF Q4):**
   ```bash
   bash tools/fetch_llm.sh   # → models/phi35.Q4_K_M.gguf (fallback: Qwen2.5-3B-Instruct Q4)
   ```
3. **Guideline knowledge base:** place guideline markdown files (YAML frontmatter:
   `guideline_id, issuing_body, year, evidence_level, context_tags`) in `guidelines/`, then:
   ```bash
   oracle kb build --guidelines guidelines/
   ```
   A synthetic dev seed set ships in `tests/fixtures/mini_guidelines/`.

## Quickstart (end-to-end)

```bash
oracle ingest   --input data/sample_study --out data/study.json
oracle segment  --study data/study.json   --out data/seg.json
oracle physics  --seg  data/seg.json      --out data/phy.json
oracle report   --seg  data/seg.json --phy data/phy.json --out data/report.md
cat data/report.md
```

Web interfaces:

```bash
oracle ui      # Gradio demo        → http://localhost:7860
oracle serve   # FastAPI REST API   → http://localhost:8000/docs
```

## CLI Reference

| Command | Purpose |
|---|---|
| `oracle --version` | Print version |
| `oracle ingest --input DIR --out F` | Parse + de-identify DICOM series → `study.json` |
| `oracle segment --study F --out F` | ONNX INT8 segmentation → `seg.json` |
| `oracle physics --seg F --out F` | EDV/ESV/EF (Simpson) → `phy.json` |
| `oracle kb build --guidelines DIR` | Build ChromaDB guideline index |
| `oracle report --seg F --phy F --out F` | Cited report + audit gate → `report.md` |
| `oracle bench --input DIR --runs 3 --out F` | Timing benchmark → `bench.json` |
| `oracle vault view --key-file P --limit N` | Decrypt + list analytics records |
| `oracle serve --port 8000` | REST API |
| `oracle ui --port 7860` | Gradio UI |

**Exit codes:** `0` ok · `2` ingest/validation · `3` model/segmentation · `4` RAG · `5` synthesis/audit · `6` vault.

## Testing

```bash
pytest -q          # offline only; synthetic DICOM + mock ONNX fixtures
ruff check .
```

Fixtures are generated by `tests/make_synthetic_dicom.py` (analytic EF ≈ 55.1%) and
`tests/make_mock_onnx.py` (deterministic single-class conv). **No PHI, no network in tests.**

## Validation Targets (ACDC test split, CPU)

| Metric | Threshold |
|---|---|
| Dice — LV / MYO / RV | ≥ 0.90 / 0.82 / 0.85 |
| HD95 — LV | ≤ 6 mm |
| EF error vs ground truth | ≤ 5 pts |
| Citation coverage (§3/§4 bullets) | 100% |
| Report determinism (temp=0) | byte-identical across runs |

Timing budget (i5-6500, median of 3): ingest ≤30 s · segment ≤240 s · physics ≤2 s ·
retrieve ≤2 s · synthesize ≤300 s · **e2e ≤600 s**. Results are recorded in
`VALIDATION_REPORT.md` (generated by Phase 8 batch runner).

## Security & Privacy

- De-identification at ingestion (name/ID/date/institution tags blanked; SHA-256 study token).
- Zero telemetry; zero network calls in the production path.
- Vault files and key files enforced at mode `0600`; Fernet-encrypted payloads.
- `models/`, `data/`, `kb/` are gitignored — weights and data never enter version control.

## Limitations & Out of Scope (MVP)

2.5D segmentation only (no 3D nnU-Net) · FFR surrogate is a documented placeholder
(`placeholder-v0`) · synthetic guideline seed set (real guideline licensing pending) ·
no EHR/HIS integration · no multi-user auth · single-study processing.
